# 设计：账号与学习数据只读审计

## 审计原则

- **事实优先**：生产数据库元数据、只读聚合结果和已发布代码路径优先于本地 README 或候选迁移的描述。
- **最小披露**：不查询或输出用户内容与身份标识；需要关联两侧时仅在执行环境内比较，经脱敏聚合后输出结论。
- **不改变状态**：所有数据库会话必须是只读；不调用可写 RPC、不触发登录、不创建临时账号，也不访问会刷新状态的用户操作路径。
- **证据可追溯**：结论需标示为“生产元数据”“本地源码”“本地候选迁移”或“未知”，避免把一种证据误当成另一种。

## 审计维度

| 维度 | 需回答的问题 | 允许证据 |
| --- | --- | --- |
| 身份与关系 | W 身份映射、C 身份、关联表和唯一性约束实际如何存在 | 表/RLS/索引元数据、脱敏关系计数、网关源码 |
| 会话与入口 | 微信登录、邮箱登录、关联/解绑端点实际把会话签发给谁，客户端如何缓存与刷新 | 网关与小程序源码、脱敏配置/版本元数据 |
| 内容归属 | `words`、语境、阅读内容等记录的拥有者字段、外键及访问控制是什么 | schema/RLS/RPC 元数据、聚合计数 |
| 学习行为与进度 | 复习事件的幂等键、词条身份、日活动和私有状态能否独立保留及重算 | 约束、索引、函数定义、聚合完整性检查 |
| 存量风险 | 是否存在旧模型的迁移/复制痕迹、重叠数据或无法判断来源的记录 | 不含正文的聚合、摘要与时间范围；未知必须明确标注 |
| 授权收敛 | 解绑后 RLS、会话、缓存和离线队列分别如何失效 | RLS/RPC 元数据与客户端/网关代码；不能由单一证据推断已安全 |

## 安全边界

1. SQL 使用 `BEGIN READ ONLY` 或等效只读通道，禁止 DDL/DML、锁表、管理认证 API 及任何写 RPC。
2. 输出只能包含 schema 名、表/函数/策略/索引名称、布尔值、计数、校验摘要、版本和风险等级。
3. 不记录原始查询返回、环境变量、请求头、用户 ID、邮箱、词条、来源 URL 或认证资料。
4. 发现疑似敏感信息或需要查看具体行才能判断时，停止该项，报告“需进一步授权的受控核验”，不扩展查询。

## 结论模型

每条结论必须采用下列之一：

| 状态 | 含义 |
| --- | --- |
| 已证实 | 有直接生产只读证据，且证据范围足以支持结论 |
| 部分证实 | 已证实一部分，但仍有明确缺口 |
| 仅本地候选 | 只在仓库 SQL/代码中存在，不能代表已部署 |
| 未知 | 缺少安全、足够的只读证据 |
| 风险 | 已证实与 V1 契约冲突或可能造成数据/授权问题 |

审计完成后不直接修改任何行为；下一项 change 必须根据结论另行提案，并把存量数据处置、生产迁移和真实账号验证拆为单独授权任务。

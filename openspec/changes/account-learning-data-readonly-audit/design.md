# 设计：账号与学习数据只读审计

## 审计原则

- **事实优先**：生产数据库元数据、只读聚合结果和已发布代码路径优先于本地 README 或候选迁移的描述。
- **最小披露**：不查询或输出用户内容与身份标识；需要关联两侧时仅在执行环境内比较，经脱敏聚合后输出结论。
- **不改变状态**：所有数据库会话必须是只读；不调用可写 RPC、不触发登录、不创建临时账号，也不访问会刷新状态的用户操作路径。
- **证据可追溯**：结论需标示为“生产元数据”“本地源码”“本地候选迁移”或“未知”，避免把一种证据误当成另一种。

## 审计维度

| 维度 | 需回答的问题 | 允许证据 |
| --- | --- | --- |
| 身份与关系 | W 身份映射、C 身份、关联表和唯一性约束实际如何存在 | 表/RLS/索引元数据、脱敏关系计数、网关源码 |
| 会话与入口 | 微信登录、邮箱登录、关联/解绑端点实际把会话签发给谁，客户端如何缓存与刷新 | 网关与小程序源码、脱敏配置/版本元数据 |
| 内容归属 | `words`、语境、阅读内容等记录的拥有者字段、外键及访问控制是什么 | schema/RLS/RPC 元数据、聚合计数 |
| 学习行为与进度 | 复习事件的幂等键、词条身份、日活动和私有状态能否独立保留及重算 | 约束、索引、函数定义、聚合完整性检查 |
| 存量风险 | 是否存在旧模型的迁移/复制痕迹、重叠数据或无法判断来源的记录 | 不含正文的聚合、摘要与时间范围；未知必须明确标注 |
| 授权收敛 | 解绑后 RLS、会话、缓存和离线队列分别如何失效 | RLS/RPC 元数据与客户端/网关代码；不能由单一证据推断已安全 |

## 安全边界

1. SQL 使用 `BEGIN READ ONLY` 或等效只读通道，禁止 DDL/DML、锁表、管理认证 API 及任何写 RPC。
2. 输出只能包含 schema 名、表/函数/策略/索引名称、布尔值、计数、校验摘要、版本和风险等级。
3. 不记录原始查询返回、环境变量、请求头、用户 ID、邮箱、词条、来源 URL 或认证资料。
4. 发现疑似敏感信息或需要查看具体行才能判断时，停止该项，报告“需进一步授权的受控核验”，不扩展查询。

## 结论模型

每条结论必须采用下列之一：

| 状态 | 含义 |
| --- | --- |
| 已证实 | 有直接生产只读证据，且证据范围足以支持结论 |
| 部分证实 | 已证实一部分，但仍有明确缺口 |
| 仅本地候选 | 只在仓库 SQL/代码中存在，不能代表已部署 |
| 未知 | 缺少安全、足够的只读证据 |
| 风险 | 已证实与 V1 契约冲突或可能造成数据/授权问题 |

审计完成后不直接修改任何行为；下一项 change 必须根据结论另行提案，并把存量数据处置、生产迁移和真实账号验证拆为单独授权任务。

## 任务 1.1：核实清单与证据边界

本地源码只能确认当前工作区中的候选设计或实现意图，不能证明生产已部署。涉及已发布网关或小程序时，生产元数据与可识别发布版本必须同时具备；缺少任一项即标为未知。后续保存的证据仅限对象名称、布尔值、计数、时间范围、校验摘要和版本。

| 维度 | 需核实的问题 | 本地源码可确认 | 必须生产只读确认 | 最小输出 |
| --- | --- | --- | --- | --- |
| 身份 | W 映射是否独立于 C；两种登录会话分别代表谁 | 候选身份表、登录路径 | 实际表/唯一约束/RLS、发布会话主体 | 对象、约束、策略、版本、布尔结论 |
| 关系 | W/C 是否一对一；确认、状态、审计、锁是否存在 | 候选关系/批次/审计/锁表 | 表、主外键、唯一约束、索引、RLS、RPC 权限、状态计数 | 对象清单、状态分组计数 |
| 双重验证 | 关联是否验证两端且须明确确认；邮箱登录是否静默关联 | 客户端入口、网关端点、协议常量 | 已发布路由/版本及是否有旧绕过路径 | 路由/版本、布尔结论 |
| 会话与收敛 | 登录/关联/解绑后会话主体；失效、缓存、离线队列、跨设备授权是否收敛 | `auth.ts`、网关、缓存与队列路径 | 发布版本、服务端校验/RLS；不能证明的离线行为 | 会话类别、缓存/队列规则、未知项 |
| 内容归属 | 词条、语境、阅读内容的所有者字段、外键和访问控制 | 候选表引用与 RLS | 实际列、外键、策略/RPC、空归属或孤立引用聚合 | 对象、策略、异常计数 |
| 行为与幂等 | 事件是否保留实际学习者、词条身份、授权依据与唯一键；重试是否去重 | 候选 `review_events`、RPC、队列幂等键 | 实际约束/索引/函数权限、重复或孤立聚合 | 约束/函数、异常计数 |
| 进度 | 是否可基于独立有效事件重算，不按拼写错误合算或相互覆盖 | 候选状态/活动表、汇总 RPC | 事件粒度、触发器/函数、来源字段、完整性聚合 | 算法对象、粒度结论 |
| 存量风险 | 是否已有身份迁移、归并、复制、日活动相加或状态覆盖 | 候选 `hc_execute_account_link` 旧模型路径 | 已应用迁移、批次/审计/manifest 的脱敏状态与时间范围 | 迁移标识、状态/操作计数 |
| C001/C002 隔离 | 更换关联时是否会泄露旧 C 内容或错误计入其事件 | 候选关联/解绑逻辑 | 关系历史、内容/事件来源与授权模型是否足够验证 | 可验证字段与未知项 |

后续只读取证覆盖：已应用迁移或等效 schema 版本；相关表、列、外键、约束、索引、触发器、RLS、函数和权限；不含身份或内容的完整性聚合；以及可识别的已发布网关和小程序版本。若须查看具体用户行、内容或认证资料才能判断，必须停止并标为“未知”或“需进一步授权的受控核验”。

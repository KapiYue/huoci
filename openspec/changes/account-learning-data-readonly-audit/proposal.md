# 账号与学习数据只读审计

## 为什么现在做

已确认的 V1 产品目标是“微信账号 W 与词鲸邮箱账号 C 保持独立身份，通过可撤销授权共享内容和可重算学习进度”。当前已归档的 `linked-wechat-login-session` 实现及本地待部署 SQL 则采用“关联后签发 C 会话、关联时迁移数据、解绑时复制数据”的旧模型。

在不了解生产库真实迁移状态、现有关系和学习数据归属前，不能安全地：

- 设计或实施 V1 授权共享；
- 处理旧模型留下的合并、复制或重复数据；
- 为正式微信账号写入、恢复或清理录制演示数据。

本 change 的作用是建立足以支撑下一项设计决策的、脱敏且可复核的事实基线。

## 目标

1. 只读核实 W/C 身份、关联关系、会话签发和页面使用路径的实际状态。
2. 只读核实学习表、RLS、RPC、索引和约束是否支持独立归属、事件去重与按授权重算。
3. 区分已部署事实、本地候选迁移和旧模型可能造成的存量风险。
4. 输出可审阅的差异报告，并提出后续 V1 改造的中型 change 边界；不预设迁移方案。

## 非目标

- 不修改小程序、网关、数据库迁移、生产配置或产品文案。
- 不登录、关联、解除关联、重置会话、创建测试账号或写入学习数据。
- 不读取、输出或保存密码、密钥、访问令牌、openid、unionid、邮箱、用户 UUID、词条正文、原句或其他敏感内容。
- 不对存量数据作恢复、删除、去重、复制、迁移或“修复”承诺。
- 不创建录制数据批次工具，也不开始视频录制工作。

## 预期交付

- 一份脱敏审计结论：现状、证据来源、与 V1 契约的差异、风险等级及未知项。
- 一张“表 / 约束 / RLS-RPC / 业务含义”清单，只保留元数据和聚合统计。
- 一份下一项候选 change 建议，明确需要用户决定的存量数据策略和生产写入边界。

## 依赖

- `AGENTS.md`、`docs/account-relationship.md`、`docs/learning-data-lifecycle.md`、`docs/account-binding-acceptance.md` 已是 V1 产品输入。
- 执行阶段若需查看生产元数据，必须使用已有的受控只读访问方式；访问不可用时记录为阻塞，不以猜测替代。

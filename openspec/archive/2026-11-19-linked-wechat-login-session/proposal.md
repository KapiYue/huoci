# 关联后微信登录会话修复

> 历史 change，当前暂停验收和归档。本文及同目录设计、规格和任务记录的是旧的“关联后 C 会话、合并与解绑复制”模型。已确认的 V1 目标改为 W/C 独立身份、授权共享与可重算进度（见 `AGENTS.md` 及 `docs/account-relationship.md`）。保留本文原始决策与实施记录供只读审计，不将其视为 V1 验收依据；不得据此直接修改线上账号数据。

## Why

已关联词鲸账号的微信用户在小程序点击“微信登录”时，线上 `POST /wx/login` 返回 HTTP 502：

```json
{"message":"无法签发关联账号会话"}
```

这违反既定账号模型：关联后的微信仍是小程序默认主登录方式，微信登录与词鲸邮箱登录必须访问同一份规范账号数据。

现有代码已经成功完成微信 code 校验、微信身份查询及关联关系查询；失败点位于为关联目标账号调用 Supabase `admin/generate_link` 生成一次性会话凭据。当前错误被安全地脱敏，但服务端日志没有足够的非敏感分阶段信息来辨别授权、认证能力开关、限流或返回体兼容问题。

## What Changes

- 为关联后微信登录补齐明确、脱敏的分阶段诊断；不得记录邮箱、微信 code、openid、magic link、token hash、access token、refresh token 或服务端密钥。
- 校验并适配 Supabase `admin/generate_link` → `/auth/v1/verify` 的线上返回契约，使微信验证成功后能为关联词鲸账号签发常规、可刷新的 session。
- 保持既有账号语义：关联后微信登录进入词鲸规范账号；解绑后微信登录恢复进入微信独立账号；邮箱登录不因关联而失效。
- 扩充网关测试与人工生产回归矩阵，覆盖独立微信、关联后微信、关联后邮箱、解绑和解绑后两种登录。
- 提供精确部署与回滚步骤；部署不运行数据库迁移、不写入/删除账号或学习数据。

## Non-goals

- 不修改 `hc_wechat_identities`、`hc_account_links` 或任何用户学习数据。
- 不通过删除关联、重建用户、重置密码或篡改身份映射来规避故障。
- 不改变普通邮箱登录为自动关联，也不改动关联、解绑的数据迁移语义。
- 不在本 change 中创建录制数据、发布体验版或调整首发功能开关。

## Risk and Rollout

该修复只改变“经新微信 code 验证后，网关如何为已关联账号获得会话”。所有身份选择仍由服务端已有映射和关联表决定，客户端不能传入目标账号 ID。

上线顺序：本地诊断与测试 → 经单独授权部署安全诊断 → 使用当前微信账号复现一次并记录非敏感阶段信息 → 基于证据实施修复与回归测试 → 经单独授权精确部署网关文件并备份 → 健康检查 → 使用当前微信账号完成一次关联后微信登录确认。任何步骤失败均回滚代码，不改数据库记录。

生产确认不使用专用测试账号，不执行解绑、重新关联或学习数据写入；只验证当前既有关联状态下能否签发正确会话。
